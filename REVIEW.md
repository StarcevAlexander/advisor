# REVIEW.md — правила ревью для advisor

## Уровни риска

| Уровень | Что затронуто | Кто проверяет |
|---|---|---|
| Высокий | `server/internal/httpapi/middleware.go` и всё про пароль/Bearer, `server/internal/config`, `server/internal/changes` (запуск правок через GitHub), миграции `server/internal/store/migrations`, `render.yaml`, `.github/workflows`, обработка вложений | Человек обязательно, ИИ-ревью только как первый проход |
| Средний | Остальной Go-код сервера, `web/src/app/services`, вызов z.ai (`server/internal/chat`) | ИИ-ревью + человек просматривает дифф |
| Низкий | Стили, вёрстка, тексты, README, тесты без изменения логики | ИИ-ревью достаточно |

## Что искать в первую очередь

1. Секреты: `ZAI_API_KEY`, `ACCESS_PASSWORD`, `GITHUB_TOKEN`, `DATABASE_URL` не попадают в код, логи, ответы API, тексты ошибок и в индекс git. `server/.env` остаётся в `.gitignore`.
2. Доступ: каждый эндпоинт, кроме `/healthz`, закрыт паролем; сравнение пароля — в постоянное время; новые маршруты не обходят middleware.
3. Вложения и ввод: лимиты размера и числа файлов, проверка типа, отсутствие записи пользовательского имени файла на диск как есть.
4. Postgres: только параметризованные запросы, миграции только добавляющие (без `DROP`/`TRUNCATE` без отдельного одобрения), сбой базы не ломает чат.
5. Правки приложения из чата (`changes`): нельзя расширить права токена, нельзя пушить в основную ветку напрямую, откат остаётся рабочим.
6. Расходы: новые вызовы z.ai имеют лимит токенов и не уходят в цикл; модель берётся из `ADVISOR_MODEL`.
7. Фронт: пароль и ответы не логируются в консоль; ошибки отправляются через `POST /api/client-error` без содержимого переписки.

## Проверки до слияния

- `go vet ./... && go test ./...` в `server/`
- `npm run build` и `npm test -- --watch=false` в `web/` (с `CI=1`)
- Изменение видимого интерфейса проверено в браузере, в том числе на ширине 375 px
- Версия поднята хуком `.githooks/pre-commit`, файл `web/src/app/version.ts` в коммите

## Что не считать замечанием

- Стиль, который уже принят в проекте (`@Service()`, signals, Signal Forms, барелы `models/` и `constants/`)
- Отсутствие комментариев в коде: по правилам проекта их не пишут
